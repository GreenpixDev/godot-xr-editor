Все прогоны — Quest 2 по Link, 90 Гц, рендер 1872×1920 на глаз, RTX 4060, пустая сцена `benchmarks/empty.tscn`, код не закоммичен (поле `git_head` указывает на начальный коммит `52c8e52`).

| Прогон | Условия | Итог |
|---|---|---|
| `2026-10-05T14-32-35` | ASW по умолчанию (Auto); первая версия замера: CSV писался между сегментами (по файлу на сегмент), без фаз | Сегменты 1–2: 100 % и 99,6 % кадров в бюджете (CPU 2,95 и 1,26 мс, GPU 1,96 и 1,42 мс). Сегменты 3–4: CPU 10,9 и 16,3 мс, 56,5 % и 0 %, рантайм на 45 Гц |
| `2026-10-05T14-43-49` | ASW Auto; один CSV в конце, фазы главного потока | Та же картина: сегменты 1–2 — 100 % и 99,5 %; с ~111 с растёт только «логика редактора» (0,65 → 9,5 → 14,7 мс) |
| `2026-10-05T14-47-36` | Задумывался с выключенным ASW, но по логу сервиса Oculus (`Service_2026-10-05_14.15.28.txt`) Oculus Debug Tool впервые подключился к сервису в 15:22 и только прочитал `asw.Mode` = `auto`; ASW оставался Auto. Фактически повтор предыдущего прогона | Совпадает с предыдущим. Что дело не в ASW, видно по фазам: ожидание композитора («до кадра свопчейна») ≤ 0,2 мс во всех сегментах, растёт только «логика редактора» |
| `2026-10-05T15-55-32` | ASW Auto (сервис ответил `asw.Mode` = `auto` в 15:22); в панели Output включена группировка дубликатов (`editor_log_collapse: true` в метаданных) | **Порог выполнен.** Все 4 сегмента ровные, 100 % кадров в бюджете, 0 пропущенных, 16 161 кадр за 180 с. UI открыт: p50 2,98 мс, p99 4,16 мс, max 10,39 мс (CPU 2,97, GPU 1,96). UI скрыт: p50 1,43 мс, p99 1,97 мс, max 7,79 мс (CPU 1,28, GPU 1,43). Группировка стоит ~0,1 мс «логики редактора» на кадр (1,92 против 1,83 мс в начале прогонов без неё) |

Причина роста (по исходникам `editor/editor_log.cpp` 4.7.2): ошибка движка `active_sets.is_empty()` приходит каждый кадр и без группировки дубликатов добавляет строку в панель Output. После `run/output/max_lines` = 10 000 строк (≈ 111 с при 90 Гц) каждое сообщение удаляет первую строку RichTextLabel (`remove_paragraph(0)`), и это стоит миллисекунды на кадр.

# Передача шлема игре и обратно (шаг 3 спайка)

`XREHandoffBenchmark` пять раз запускает `benchmarks/xr_handoff_game.tscn` штатным Play редактора; игра выходит сама через 5 с после получения фокуса. Время — по системным часам обоих процессов.

| Прогон | Условия | Редактор → игра | Игра → редактор |
|---|---|---|---|
| `handoff_2026-10-05T17-25-48` | ASW Auto, 90 Гц; окно игры встроено в плавающее окно редактора (по умолчанию: `game_embed_mode` 0, `embed_on_play` и `make_floating_on_play` — true) | 5 из 5; медиана 2,29 с, max 2,53 с; из них запуск процесса до `_ready` — 2,22–2,51 с | 5 из 5; медиана 0,05 с, max 0,10 с |

Сессия редактора на время игры переходит VISIBLE → SYNCHRONIZED и обратно в FOCUSED; редактор свою сессию не завершает. По словам пользователя, переход в шлеме мгновенный, без чёрного экрана.
