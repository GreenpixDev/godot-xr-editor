# Обоснования инвариантов и подробности правил кода

Вынесено из CLAUDE.md. Читать, когда правило непонятно или нужно его обосновать.

## Инварианты

1. Через `XREDocument` ([core/document.gd](../addons/xr_editor/core/document.gd)) действие из шлема отменяется с клавиатуры, попадает в лог и не ломает запасной путь. Перетаскивание — `preview_transform` каждый кадр и один `commit_transform` в конце; группа — один `commit_transforms` на все узлы (D-120).
2. Риг, руки, меню, гизмо живут в дереве редактора (под плагином / его SubViewport), никогда под `get_edited_scene_root()` и без `owner`. Они рисуются на отдельном visual layer, скрытом от камеры настольного 3D-вьюпорта.
3. XR-`SubViewport` (`use_xr = true`) берёт `world_3d` 3D-вьюпорта редактора; синхронизировать нечего.
4. В покадровом коде нет аллокаций, `get_node`, `find_child` и рейкастов по всей сцене; горячие пути — в GDExtension; приёмы и цены — [performance_rules.md](performance_rules.md). При входе в VR low-processor mode выключается, ограничение FPS снимается.
5. Доля операций через панели — метрика исследования; операция в обход документа — потерянные данные.
6. Исходник — граф, артефакт — GDScript.
7. Вариант фичи (D-039): не заменяет прежний и не живёт в ветке, константе или флаге командной строки. Значение добавляется в существующую настройку `XREFeatureSettings.DEFINITIONS`, если варианты взаимоисключающие (Billboard/Cuboid в Node display), или новая настройка, если измерение независимое. Категория — `FEATURES` (как выглядит и ведёт себя) или `CONTROLS` (какой ввод что делает); первый вариант — по умолчанию и сохраняет текущее поведение. Инструменты читают `XREDocument.features`, перестраиваются по сигналу `changed`; меняют значение только через `XREDocument.set_feature`. Тесты проверяют каждый вариант; запись в `decisions.md` называет варианты и что сравнивается.

## Перезапуск редактора

Решение автора 2026-10-19. Открытый редактор держит нативную библиотеку (`~xre_native…dll`) и работает со старой версией плагина; headless-редактор её не загрузит. `scripts/xr_editor.py` сам закрывает редактор проекта (несохранённое теряется), ждёт освобождения библиотеки и запускает заново. `--no-restart` — только по просьбе автора.

## Код

- `@tool` нужен, потому что скрипты аддона исполняются в редакторе. Исключение `playmode/return_to_editor.gd`: автозагрузка с не-`@tool` скриптом в редакторе создаётся, но в дерево не добавляется и не исполняется.
- Ошибки движка (D-003): `untyped_declaration` (включая параметры, возвраты, переменные цикла: `for node: Node in nodes`), с 2026-10-05 также `unsafe_property_access` и `unsafe_method_access` — обращение к несуществующему свойству (`SubViewport.update_mode`) иначе всплывает только в шлеме. `:=` допустим.
- Сигналы редактора отключаются в `_exit_tree`, потому что плагин перезагружается при каждом выключении/включении.
- `##` doc-комментарии: из них генерируется справка API для приложения к диплому.

## Подводные камни Godot 4.7

- Предупреждения GDScript в `addons/` выключены по умолчанию; аддон включён через `debug/gdscript/warnings/directory_rules` в `project.godot` (`1`). Не удалять.
- `load()` возвращает объект скрипта даже при ошибке парсинга; сломанный отличает `can_instantiate() == false`.
- Headless без `--xr-mode off` пытается поднять OpenXR и сыплет ошибками.
- `*.gd.uid` коммитить; скрипты переименовывать и перемещать вместе с `.uid` (или из редактора).
- `--log-file` не создаёт папку: без `logs/` лог молча не пишется.
- В headless рендер — заглушка: AABB мешей пустые, `RenderingServer.instances_cull_ray` их не находит, пикер ничего не видит. Тестовые сцены задают `custom_aabb` (`scripts/test_tools.gd`). `TriangleMesh` и CSG работают.
- `EditorUndoRedoManager` не даёт скрипту ни `undo()`, ни `redo()`. Вызов их у `UndoRedo` из `get_history_undo_redo` расходится со стеками менеджера: Ctrl+Z и док History потом отменяют не то. Отмена из шлема выбирает пункт Scene → Undo (id 13) или Redo (id 14) сигналом `id_pressed` (D-087). В тестах прямые вызовы допустимы.
- `EditorInspector` хранит голый указатель на то, что редактирует, и разыменует его в следующем `edit()`: RefCounted (прокси) освобождать только после `edit()` другого объекта или `edit(null)` (D-092).
- Две смены сцены редактора за кадр (`open_scene_from_path`, при выделении) — use after free и SIGSEGV в 4.7.2: док Scene откладывает `scroll_to_item` с `TreeItem*`, а вторая смена очищает дерево. Одна смена за кадр (D-092).
- Свёрнутое окно редактора усыпляет главный цикл (`OS::add_frame_delay` при `window_can_draw() == false`): в VR не сворачивать, фокус терять можно.
