# Blueprints 2D: прототип 0.3.1

Отдельный аддон `addons/blueprints/` для Godot **4.7.x**. Работает без XR Editor, шлема, OpenXR и нативной библиотеки. Добавляет вкладку **Blueprints** в центральную область редактора. Граф плоский, но может управлять как 2D-, так и 3D-нодами.

Это реализация графа для T2, не полный аналог Unreal Blueprints. Отдельный аддон описан в D-021, типы, события и ожидания — в D-022 в [дневнике решений](decisions.md).

## Быстрая проверка

В хост-проекте аддон уже включён. Открыть Godot без XR:

```powershell
godot.cmd --path . --editor --xr-mode off res://benchmarks/blueprint_door.tscn
```

1. Открыть сцену `benchmarks/blueprint_door.tscn` и ресурс `benchmarks/blueprint_door.tres` двойным щелчком в файловой системе. Появится вкладка Blueprints.
2. Нажать **Focus graph**, если графу мало места. Кнопка переключает штатный режим Godot, скрывающий боковые док-панели.
3. Розовый выход `toggled_on` события `Switch.toggled` передаёт значение в `Set Variable requested_open`. `Get Variable` подаёт состояние в Branch. Каждая ветка запускает анимацию двери с `wait = true`; надпись меняется только после её завершения.
4. Запустить сцену через F6. Переключатель **Open door** открывает и закрывает дверь.
5. Во время движения быстро переключить кнопку назад. `policy = restart` отменяет старую цепочку: надпись соответствует последнему переключению, старое ожидание не продолжает работу.
6. Остановить игру. Выбрать **Play Animation**, выключить `wait`, нажать Save и снова F6: теперь надпись меняется сразу при запуске. Вернуть `wait`, чтобы снова менять её после завершения.

В хост-проекте OpenXR включён для VR-разработки. Если запуск из редактора пытается забрать шлем, для этого плоского примера использовать отдельный запуск:

```powershell
godot.cmd --path . --xr-mode off res://benchmarks/blueprint_door.tscn
```

В чистом проекте с выключенным OpenXR достаточно F6.

## Установка в другой проект

Скопировать **только `addons/blueprints/` целиком**, вместе с `.gd.uid`, в другой проект Godot 4.7.x. Включить **Blueprints 2D** в Project → Project Settings → Plugins. Папка `addons/xr_editor/` и GDExtension не нужны. При желании скопировать `benchmarks/blueprint_door.*` для демонстрации.

## Создание своего графа

1. Во вкладке Blueprints нажать **New**. В новом графе уже есть **On Ready**.
2. Добавлять блоки двойным щелчком в списке слева или кнопкой **Add selected block**. Поиск фильтрует список.
3. Соединять выход справа со входом слева. Белые связи задают порядок выполнения. Данные имеют конкретные типы: bool, int, float, String, Vector2/3, Color и Object; универсальный голубой порт Variant принимает любой тип данных. int можно подключить к float, обратное преобразование не выполняется автоматически. Типы показаны в подсказке строки портов.
4. Настраивать выбранный блок справа. Текст и числа применяются по Enter или при выходе из поля. Подключённый вход данных заменяет соответствующее значение параметра, заданное в блоке.
5. **Save** сохраняет `.tres` и строит соседний `<имя>.generated.gd`. **Build .gd** делает то же явно. Вкладка **Generated GDScript** показывает предварительный результат текущего графа.
6. Выделить одну ноду в дереве сцены и нажать **Attach to selected**. Аддон назначит сгенерированный скрипт. Сохранить сцену обычным Ctrl+S.
7. Запустить сцену. Граф выполняется только в игре: сгенерированный скрипт намеренно без `@tool`.

Если нода уже использует другой скрипт, аддон откажется его заменять. Можно добавить обычную дочернюю `Node`, назначить граф ей и адресовать соседей через `../ИмяНоды`.

`target` — путь относительно **ноды с назначенным скриптом**: `.` — она сама, `Door` — дочерняя нода, `../Door` — соседняя. `property` — имя свойства Godot; допустимы пути к компонентам вроде `position:x`.

## Объекты, свойства и аргументы сигналов

**Script host…** выбирает ноду, на которой будет работать скрипт. **Choose from scene…** в параметре target показывает дерево текущей сцены. При смене хоста известные цели сохраняются, а пути пересчитываются относительно нового хоста. Назначение через Attach тоже устанавливает хост на выбранную ноду.

Граф хранит свою сцену в `scene_path` (это только контекст редактора). Переключение вкладок сцен не меняет Target, аргументы сигналов или типы свойств. Если активна другая сцена, появляется нейтральное сообщение **Graph belongs to …** и кнопка **Open graph scene**. Поле Target временно доступно только для чтения, без красного `missing target`; выбор целей и сборка требуют вернуться к сцене графа. Возврат вкладкой или этой кнопкой восстанавливает обычную проверку. Если цель удалена именно в сцене графа, ошибка `missing target` остаётся настоящей ошибкой.

Закрытие сцены не перепривязывает граф к оставшимся вкладкам. Сохранённую сцену можно открыть кнопкой; закрытая несохранённая сцена отмечается как недоступная. Старые графы без `scene_path` при первом открытии получают контекст по ноде с их скриптом или одноимённой соседней `.tscn`, а если таких данных нет — по сцене, выбранной при открытии. Новая привязка записывается при сохранении графа; runtime-пути и сгенерированный код от неё не зависят.

При ручном вводе Target сразу появляются подсказки подходящих путей: выбрать мышью, стрелками и Enter или дополнить через Tab. Если объект не существует, поле подсвечивается красным, под ним и в tooltip показано ровно `missing target`. Сообщение исчезает после исправления пути. Неправильное значение остаётся в черновике графа, но Save/Build/Attach не строят скрипт, пока цель не исправлена.

Пригодность проверяется по блоку: AnimationPlayer для анимации, AudioStreamPlayer/2D/3D для звука, наличие свойства или сигнала, доступность свойства для записи и возможность Tween. Неподходящий тип в дереве недоступен для выбора. Ноды подходящего типа с отсутствующим выбранным членом отмечены предупреждением: их можно выбрать и затем настроить свойство, сигнал или анимацию. Подсказки ручного ввода показывают уже подходящие цели и учитывают подключённые порты. Вне редактируемой сцены статические цели не разрешаются.

Если Target подключён проводом, путь служит необязательным образцом для схемы свойств и не получает `missing target`: объект поступит из события во время игры. Подключение объекта к Value не заменяет Target.

Для выбранной цели появляются списки её свойств, сигналов и анимаций. Свойство задаёт тип порта чтения/записи; при подключении несовместимого значения граф отклоняет связь. Неподключённые значения также проверяются при компиляции. Списки можно дополнить ручным вводом, например `position:x`.

У On Signal появляются выходы с именами и типами аргументов. `body_entered.body`, например, можно подключить к фиолетовому входу Target у Get/Set Property: действие будет адресовано вошедшему телу, а не заранее выбранной ноде. Для выбора свойства такого тела можно выбрать существующую ноду как образец; подключённый Target заменяет этот путь во время игры.

Аргументы принадлежат одному запуску события и сохраняются после Delay/ожиданий. Цепочка другого события не может использовать их: компилятор сообщит номера конфликтующих блоков. Классы объектов внутри категории Object пока не проверяются статически; наличие свойства и его тип проверяются при выполнении.

Пока граф открыт, документ удерживает слабые ссылки на выбранные объекты и обновляет пути после переименования или смены родителя, в том числе при Undo. Это не постоянные идентификаторы нод: если переименовать сцену при закрытом графе или в другом редакторе, нужно проверить и восстановить цели. Удалённая цель даёт ошибку перед сборкой; динамическая цель из аргумента проверяется во время игры.

## Переменные и ожидания

**Variables…** добавляет переменную с именем и типом и позволяет редактировать её начальное значение. Есть bool, int, float, String, Vector2, Vector3 и Color. **Get Variable** читает актуальное состояние, **Set Variable** записывает его. Значение хранится в отдельном экземпляре скрипта; начальные значения из графа общие для экземпляров. Используемую переменную нельзя удалить, пока ссылающиеся блоки не изменены или не удалены.

У Ready и Signal есть `policy`:

| Значение | Повторное событие во время незавершённой цепочки |
| --- | --- |
| parallel | Запускает независимую цепочку со своими аргументами |
| ignore | Пропускает повтор до завершения текущей цепочки |
| restart | Отменяет старые запуски этого события, их Tween и ожидаемые анимации, затем запускает новый |

Отмена не откатывает уже выполненные записи в свойства и переменные. Политика относится к одному блоку события, а не ко всем событиям графа. При parallel цепочки всё равно обращаются к общим объектам сцены; одновременное управление одним AnimationPlayer может прервать другую цепочку.

**Play Animation** с `wait = true` ждёт именно указанную анимацию, затем продолжает цепочку. Зацикленную анимацию ждать нельзя. Удаление цели, остановка, замена анимации и истечение `timeout` прекращают цепочку с ошибкой блока. Timeout задаётся в секундах реального времени; его нужно увеличить для длинных анимаций или длительной паузы. `wait = false` сохраняет прежнее поведение: сразу перейти к следующему блоку.

Runtime-ошибки содержат ID блока и сообщение. Сгенерированный скрипт также выдаёт сигнал `blueprint_error(block_id, message)`; при подключённом обработчике он отвечает за показ/запись ошибки, иначе сообщение идёт в Output.

## Циклы исполнения

С 0.3 можно соединять выход исполнения с более ранним входом, включая вход того же блока. Вход исполнения допускает одновременно стартовую и обратную связь, выход по-прежнему имеет один провод. Например: **Ready.Then → Print.In**, **Print.Then → Delay.In**, **Delay.Finished → Print.In**. Добавить Delay с `seconds = 1`, чтобы печатать с заданной паузой. Обратное ребро создаётся и отменяется обычной операцией графа в 2D и VR.

Для выхода из цикла использовать **Branch**: Condition читается заново при каждом посещении. True ведёт в повторяемую цепочку, её последний выход возвращается в Branch.In, False — в продолжение после цикла. Условия можно получать через Get Property или Get Variable; другое событие может менять переменную. Замкнутые зависимости **данных** (например Equal → Equal → первый Equal) остаются ошибкой.

Сгенерированный скрипт переходит между блоками итеративно, без растущей рекурсии. После 64 шагов он уступает следующий кадр; длинная обычная цепочка также может перейти на следующий кадр. Это защита выполнения, а не заданная частота цикла: для времени использовать Delay/Tween/ожидаемую анимацию. Цикл сохраняет политику события, его аргументы и отмену при выходе из сцены. Для бесконечного события выбирать ignore или restart, если не нужны параллельные циклы от каждого повторного сигнала. Чтобы включить новое выполнение в старом графе, сделать **Build & Attach**; формат ресурса остаётся v2.

## Блоки

| Блок | Назначение |
| --- | --- |
| On Ready | Запускает цепочку при `_ready()` ноды |
| On Signal | Подписывается на сигнал выбранной ноды и выдаёт типизированные аргументы |
| Print | Выводит значение в Output |
| Set Property | Меняет свойство целевой ноды |
| Tween Property | Плавно меняет свойство и продолжает цепочку после завершения |
| Branch | Выбирает выход True или False по булевому входу |
| Delay | Продолжает цепочку после заданного числа секунд |
| Play Sound | Вызывает `play()` у AudioStreamPlayer / 2D / 3D и сразу продолжает |
| Play Animation | Запускает анимацию; опционально ждёт завершения с отменой и timeout |
| Value | Константа: текст, int/float, bool, Vector2/3 или Color; порт типа значения |
| Boolean | Булева константа с розовым портом для Branch |
| Get Property | Читает актуальное значение свойства, когда оно требуется действию |
| Equal | Сравнивает два значения и выдаёт bool |
| Get Variable / Set Variable | Читает / записывает типизированное состояние экземпляра графа |

## Отмена, сохранение и границы

- **Undo/Redo** и Ctrl+Z / Ctrl+Shift+Z во вкладке графа отменяют изменение блоков, параметров, связей и групповой перенос. Поля ввода сохраняют собственную текстовую историю. Назначение скрипта отменяется обычной историей сцены, например в 2D-вкладке.
- При общем «Сохранить всё» / «Сохранить и выйти» граф без имени сохраняется в `user://blueprints_unsaved.tres` и восстанавливается при следующем включении аддона. После восстановления нужно нажать Save и выбрать `.tres` в проекте.
- Источник — `.tres`; `.generated.gd` — заменяемый результат. Ручные изменения сгенерированного кода теряются при следующей сборке. Обратного преобразования GDScript в граф нет.
- Генератор не заменяет файл `.generated.gd`, если в нём нет его служебного заголовка. Скрипты пользователя на нодах тоже не заменяются.
- Сгенерированный скрипт не требует аддона во время игры и может поставляться без редактора графа.
- Один выход исполнения имеет одну связь; цепочки могут сходиться. Один вход данных имеет один источник; выход данных может использоваться несколькими блоками.
- Циклы зависимостей данных запрещены; циклы исполнения разрешены. Максимум 256 блоков. Нет функций пользователя, произвольных вызовов методов, коллекций/структур, spawn/destroy и визуальной отладки.
- Формат графа — версия 2. Первая версия открывается с миграцией в памяти; новые свойства записываются только при сохранении. Старые события по умолчанию сохраняют parallel, старые Play Animation — `wait = false`.
- Первое пространственное представление доступно с XR Editor: [Blueprints VR](blueprints_vr.md), D-025. Оно разделяет документ и историю с GraphEdit; компилятор игнорирует редакторскую глубину карточек. Самостоятельная установка 2D-аддона сохранена.
- С 0.3.1 VR сохраняет положение рабочей группы и центр раскладки в графе. Первое открытие в VR задаёт место; повторное открытие сохраняет его после Save draft/Back to scene и перезапуска редактора. Данные размещения не влияют на 2D-позиции или сгенерированную логику; старые графы получают размещение при первом VR-открытии.

## Проверки

`scripts/check.sh` включает `test_blueprints.gd` (валидатор, сохранение, undo/redo, компиляция и исполнение) и `test_blueprint_editor.gd` (настоящий headless-редактор: отображение, перенос, удаление, назначение скрипта и история сцены). Визуальную проверку можно повторить:

```powershell
godot.cmd --path . --editor --xr-mode off --rendering-method gl_compatibility res://benchmarks/blueprint_door.tscn -- --xre-test-blueprint-editor
```

Редактор выполнит проверки, сохранит снимок в `build/blueprint_tests/editor.png` и закроется. Сцена-пример на диск при этом не пересохраняется.
