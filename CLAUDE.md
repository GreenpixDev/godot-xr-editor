# CLAUDE.md

VR-редактор сцен для Godot 4.7 в виде EditorPlugin — дипломная работа (октябрь 2026 — июнь 2027). Задача — собрать сцену, оживить её логикой и протестировать, не снимая шлем, и честно измерить, где VR выигрывает у настольного редактора, а где проигрывает. Рабочая база — прототип, но научный результат — это паттерны взаимодействия и числа из эксперимента.

- [docs/plan.md](docs/plan.md) — источник истины: RQ1–RQ3, MVP, архитектура, задачи эксперимента T1–T3, риски, сроки.
- [docs/decisions.md](docs/decisions.md) — дневник решений (D-001…).

## Текущий этап

Снятие главного технического риска (первые две недели, раздел «Следующие шаги» в плане): держит ли процесс редактора OpenXR и 90 Гц. Порог: ≥95% кадров ≤ 11,1 мс на пустой сцене при выключенном low-processor mode — остаёмся в EditorPlugin; иначе переход на отдельное runtime-приложение (D-002). UI и инструменты до этого решения не пишем.

Что уже известно (Godot 4.7, `modules/openxr/openxr_api.cpp`, `OpenXRAPI::openxr_is_enabled`): при `xr_mode == default` редактор OpenXR не стартует — стоит явная проверка `is_editor_hint()`. Флаг `--xr-mode on` эту проверку обходит. Работает ли после этого рендер в шлем из редактора — вопрос спайка.

*Обновлять этот раздел при переходе к следующему этапу.*

## Жёсткие ограничения

- **Godot 4.7.x, без обновлений** до конца исследования (условие воспроизводимости). Установлен 4.7.2: `godot` в Git Bash, `godot.cmd` в PowerShell → `%LOCALAPPDATA%\Programs\Godot\`. API из 4.8+ не использовать.
- **Объём.** Функция входит, только если нужна для задач T1–T3 (таблица MVP в плане). Всё остальное — в future work, не в код. Если просят что-то вне MVP — сказать об этом, прежде чем делать.
- **Движок не форкаем.** Не хватает хука — обход в GDScript/GDExtension, затем PR в upstream. Локальных патчей движка нет.
- **Данные участников** (аудио, анкеты, логи с идентификаторами) никогда не попадают в git: только `study/data/raw/` (в .gitignore).

## Архитектурные инварианты

Отступление от любого пункта — только с записью в `docs/decisions.md`.

1. **Сцена меняется только через `XREDocument`** ([core/document.gd](addons/xr_editor/core/document.gd)). Инструменты, UI и граф не вызывают `EditorInterface` / `EditorUndoRedoManager` и не пишут в редактируемые ноды напрямую. Перетаскивание — `preview_transform` каждый кадр и один `commit_transform` в конце. Так действие из шлема отменяется с клавиатуры, попадает в лог и не ломает запасной путь.
2. **VR-слой не попадает в .tscn.** Риг, руки, меню, гизмо живут в дереве редактора (под плагином / его SubViewport), никогда под `get_edited_scene_root()` и без `owner`. Они рисуются на отдельном visual layer, скрытом от камеры настольного 3D-вьюпорта.
3. **Один `World3D`, никаких копий.** XR-`SubViewport` (`use_xr = true`) берёт `world_3d` 3D-вьюпорта редактора. Код синхронизации плоского и VR-вида не пишется — синхронизировать нечего.
4. **Бюджет кадра 11,1 мс.** В покадровом коде нет аллокаций, поиска по дереву (`get_node`, `find_child`) и рейкастов по всей сцене; горячие пути — в GDExtension. При входе в VR low-processor mode выключается, ограничение FPS снимается.
5. **Каждая операция пользователя логируема**: тип, источник (3D-инструмент или 2D-панель), время. Доля операций через панели — метрика исследования; операция в обход документа — потерянные данные.
6. **Граф логики** хранится ресурсом `.tres` рядом со сценой и компилируется в читаемый `.gd` на ноде. Исходник — граф, артефакт — GDScript.

## Структура

```
addons/xr_editor/          плагин (всё, что поставляется)
  plugin.cfg, plugin.gd    точка входа EditorPlugin; владеет XREDocument
  core/                    XREDocument и его реализации
project.godot              хост-проект для разработки (OpenXR и XR-шейдеры включены)
openxr_action_map.tres     action map по умолчанию, создан Godot
scripts/check.sh           проверка без шлема
scripts/parse_all.gd       загрузчик всех скриптов для check.sh
docs/                      план и дневник решений (на русском)
```

Модули по мере надобности — не заводить пустыми папками: в аддоне `xr/` (сессия, риг, вьюпорт), `tools/` (выбор, манипуляция, снап), `ui/` (палитра, радиальное меню, панели-текстуры), `logic_graph/`, `playmode/` (передача OpenXR-сессии), `telemetry/`; в корне `benchmarks/` (эталонные сцены для замеров), `study/` (протокол, анкеты, анализ), `gdextension/` (C++).

## Команды

```bash
scripts/check.sh                              # все скрипты парсятся и типизированы, плагин грузится в headless-редакторе
godot --path . --editor                       # обычный редактор
godot --path . --editor --xr-mode on          # редактор с принудительным OpenXR (спайк)
```

## Проверка

- После любого изменения GDScript — `scripts/check.sh`, должен закончиться `check: OK`.
- Поведение в шлеме Claude проверить не может. Для VR-изменений — дать короткий чек-лист: что запустить, что сделать руками, что должно произойти, какой вывод или замер прислать обратно. Не писать «работает», пока пользователь не подтвердил.
- Числа (время кадра, задержки, проценты) — только из замеров, не из оценок.

## Код

- GDScript 4.7, `@tool` на каждом скрипте аддона: они исполняются в редакторе.
- **Статическая типизация обязательна и проверяется движком** (D-003): `untyped_declaration` = ошибка, включая параметры, возвраты и переменные цикла (`for node: Node in nodes`). `:=` допустим.
- Глобальные классы с префиксом `XRE` (`XREDocument`); файлы в snake_case; отступы табами.
- Код, идентификаторы, комментарии и сообщения коммитов — на английском. Документация в `docs/` и общение — на русском.
- `##` doc-комментарии на публичных классах и методах: из них генерируется справка API для приложения к диплому.
- Сигналы редактора, подключённые в `_enter_tree`, отключаются в `_exit_tree`: плагин перезагружается при каждом выключении/включении.

## Подводные камни Godot 4.7

- Предупреждения GDScript в `addons/` по умолчанию выключены. Наш аддон включён через `debug/gdscript/warnings/directory_rules` в `project.godot` (`1` — включить). Не удалять.
- `load()` возвращает объект скрипта даже при ошибке парсинга; сломанный скрипт отличает только `can_instantiate() == false`.
- Headless-запуск проекта без `--xr-mode off` пытается поднять OpenXR (он включён в настройках) и сыплет ошибками.
- Рядом со скриптами лежат `*.gd.uid` — коммитить. Переименовывать и перемещать скрипты вместе с `.uid` (или из редактора).
- Удалённая через `remove_child` нода теряет `owner` у себя и потомков, если владелец больше не предок. Undo удаления должен восстанавливать owner — см. `XREPluginDocument.remove_node`.
